# FloodShield — план разработки работающего демо

Дата: 27 октября 2026. Цель первой версии: интерактивно исследовать, как осадки, насыщение грунта, рельеф и водоотведение меняют приоритет обследования участков.

## Порядок работ
1. Сохранить этот план до реализации.
2. Сделать самостоятельное веб-приложение с картой условного района, выбором участка, управлением осадками, насыщением грунта и состоянием водоотведения.
3. Реализовать прозрачную демонстрационную модель поверхностного стока: расчёт эффективных осадков, распределение по водосбору, накопление в понижениях и отвод воды. Все исходные значения и упрощения доступны в интерфейсе.
4. Добавить три воспроизводимых сценария, сравнение с исходным состоянием, список участков по приоритету, объяснения факторов, сохранение сценария и экспорт JSON.
5. Проверить модель автоматическими тестами: отсутствие осадков, рост дождя, насыщение, водоотвод, баланс воды, неправильные входы. Проверить взаимодействия в браузере и мобильную компоновку.
6. Опубликовать личное демо и передать ссылку вместе с этим Markdown.

## Границы первой версии
Геометрия района, высоты, водоотвод и характеристики грунта синтетические. Карта не описывает реальную Астану. Результат — индекс приоритета обследования в условном сценарии; он не является вероятностью затопления или официальным оповещением. Вода на схеме показывает расчёт накопления в упрощённой модели, а не прогноз глубины у реальных домов.

## Проверка модели
Модель рассчитывает объём эффективных осадков на каждом участке и передаёт воду только вниз по заданному графу. Есть начальная ёмкость удержания и подтверждённые единицы. Экспорт включает параметры, версию модели, синтетическое происхождение и полный водный баланс. Недопустимые параметры отклоняются. Дренаж учитывается только в рамках выбранной продолжительности дождя.

## Развитие до хакатона
- Заменить условный район небольшим реальным водосбором: проверить DEM, дорожную сеть, водоотвод, историю затопления и лицензии.
- Выделить историческое событие для независимой оценки; данные после события не использовать как вход в ретроспективный прогноз.
- Подключить Meta Model API на сервере: извлечение места/времени/наблюдений из полевых материалов с источниками и подтверждением оператора. Понимание документов не заменяет гидрологическую модель.
- Сравнить полезность ранжирования с простой базовой моделью и экспертной оценкой. Не заявлять точность и предотвращённый ущерб без измерений.
- Проверить полные правила участника: публичная тема Push the Frontier подходит по направлению; соответствие финальной реализации зависит от реальной роли Meta и правил. Разрешение сторонних AI-помощников разработки пока не подтверждено доступными полными правилами.

## Критерии готовности текущего демо
Все основные кнопки работают, сценарии пересчитываются, выбор участка меняет карточку, расчёт повторяем, данные сохраняются локально, JSON экспортируется, тесты проходят. Интерфейс прямо сообщает об условных данных и отсутствии подключённого Meta API.

## Реализовано в версии 0.2 — 30 октября 2026

- Переработан интерфейс вокруг сценария «условия → наблюдение → проверка → сравнение вмешательства»; есть английская и русская версии.
- Добавлен управляемый показ для жюри, блокирующий переход до подтверждения сообщения.
- Добавлены локальные вмешательства дренажа и проверяемый расчёт при неизменных осадках.
- Подключены реальные исторические геометрии CEMS Valencia Sud, отдельно от модели, с происхождением и лицензией.
- Реализован серверный Meta adapter, проверка цитат/схемы, таймаут и честный статус отсутствия ключа. Живой ключ не настроен.
- Расширены тесты до 38, подготовлены self-contained Worker, локальный Node-сервер, CI, README, описание показа и лицензия.
- Публичная публикация исходников в GitHub запрошена пользователем. Подготовка репозитория выполняется после проверки кода; создание через браузер требует входа пользователя, поскольку GitHub-коннектор не предоставляет создания репозитория.

Следующие содержательные задачи: реальный вызов Meta и отложенная оценка извлечения; экспертная проверка модели; реальный небольшой водосбор с независимой валидацией. Текущий прототип не выдаётся за завершённую систему предупреждения.
